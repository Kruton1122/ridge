# Ridge redesign

The redesign **is** the live site as of 2026-09-10. The previous site is archived
at `/old`. `/new/*` redirects to the same path without the prefix. `/source`
redirects to `/api`.

*Built by Claude, 2026-09-10; promoted the same day. Product rules still live in
[`RIDGE.md`](./RIDGE.md); agent ownership in [`RIDGE-BOT.md`](./RIDGE-BOT.md).*

## The one rule that matters

**The redesign never writes to a file Ridge Bot's pipeline writes.**

`scripts/apply-briefing-staging.py` writes exactly four paths:

| Path | Owner |
|---|---|
| `src/lib/data/catalog.ts` | Ridge Bot |
| `src/lib/data/desk.ts` | Ridge Bot |
| `src/lib/data/changelog.ts` | Ridge Bot |
| `public/llms.txt` | Ridge Bot |

Every route **reads** those four and writes none of them. A daily scrape lands
on the site with no second edit and no merge conflict. The 7:30am cron
(`/etc/cron.d/ridge-briefing`) was not touched, and neither were nginx,
`ridge.service`, the Cloudflare tunnel, or any port.

## What was modified

Two files, both additively:

- **`src/styles.css`** — a clearly fenced block appended at the end defining the
  `n-` design tokens and utilities. No existing token or rule was changed, so the
  published site renders byte-identically. Deleting that block rolls back the
  whole design system.
- **`src/routeTree.gen.ts`** — regenerated by the TanStack Router plugin. Not
  hand-edited.

`src/lib/data/ledger.ts` was deliberately **not** touched: `buildLedger()` drives
`/api/ledger.json` and `/api/ledger.csv`, which are a public contract. The
redesign's table uses `ledgerRows()` in `derived.ts` instead, which walks the
whole catalog rather than only the AA-scored rows, so unscored models appear with
a dash instead of being dropped.

## For Ridge Bot

Nothing changes about the daily routine. Specifically:

- Keep writing `catalog.ts`, `desk.ts`, `changelog.ts`, `llms.txt` exactly as now.
- `publicOpinionStars` / `publicOpinionNote` / `publicOpinionAsOf` are read and
  rendered on `/models/$slug`, same contract as the old model page. Do not
  remove them.
- `WireItem` and `NewsItem` shapes are unchanged and are read by `/news`.
- If a **new field** is added to `Model`, the site ignores it until someone wires
  it up — it will not break.
- If a **field is renamed or removed**, the build breaks at typecheck. Run
  `npm run typecheck` before committing a schema change.

Three pre-existing bugs on the **published** site were found during this work
and fixed on the owner's say-so:

1. **`/news/$id` served the wrong page.** `src/routes/news.tsx` was the parent
   route of `src/routes/news.$id.tsx` and rendered no `<Outlet />`, so every desk
   article URL silently returned the news *list*. Renamed to `news.index.tsx`,
   which makes the two siblings. All nine desk articles now render — several had
   never been reachable. Note that the router's incremental codegen left a
   dangling `NewsRoute` reference after the rename and the dev server needed a
   restart to regenerate `routeTree.gen.ts` cleanly; check the generated file
   after any route rename.
2. **`profiles.ts` quoted stale scores.** Its `voice` / `strengths` / `watch`
   strings carried AA numbers from the 7 September cut that later pulls had moved,
   and the published model pages rendered them. The file no longer contains any
   benchmark number at all — see the header comment there. Scores live in
   `catalog.ts`, which the scrape owns; `profiles.ts` now carries only what does
   not drift.
3. **The daily apply matcher corrupted scores it should have skipped.** Weak
   fuzzy matches in `scripts/apply-briefing-staging.py` let a low-confidence
   Arena/SWE row overwrite a good one — the 07:30 cron on 2026-09-10 dropped
   Fable 5.1's Arena Elo from 1520 to 1178 and Opus 5's SWE-bench from 97 to 76.4.
   Root-caused and fixed: exact/alias matches are now preferred, a model is
   "claimed" by its first confident match so a later weak row cannot overwrite
   it, non-main Arena rows (style-control, deprecated, ancient Claude-1/2) are
   skipped outright, and any fuzzy match moving a score past a per-benchmark
   delta ceiling without high confidence is rejected and logged instead of
   applied. See `RIDGE-BOT.md` for the full note and the changelog entry for
   the correction.

## Design decisions worth knowing

- **No hero.** A masthead band, then the board. Peer ledger sites go
  near-straight to data; a hero with a CTA reads as a SaaS landing page.
- **Amber is signal only** — active state, rank 1, links, bars. Never decoration.
  Lab brand colors appear only as a 7px dot and as bar fill, never as a row
  background, or the table turns into a clown suit.
- **Serif for voice, sans for numbers.** Newsreader on headlines and essays;
  Source Sans with `tabular-nums` on every figure. Serif numerals in a data table
  are the classic tell.
- **Every score carries its source inline**, not in a footnote. That discipline is
  the thing Ridge does that the larger boards do not, so it is made visible.
- **Ranks carry denominators** (`#3 of 10`). A score without one is a claim; with
  one it is a measurement.
- **Empty cells are content.** The board shows all 20 catalog rows, not just the
  10 with AA scores, and the homepage has a section naming the unscored ones.

### Everything is catalog-driven (verified, not assumed)

Ridge Bot edits `catalog.ts`; the site reshapes itself. No component holds a list
of models, labs or benchmarks.

| Ridge Bot adds… | What happens |
|---|---|
| A **score** for an existing model | Board, bars, ranks, `$/AA`, scatter, timeline, dossier all move |
| A **model** | Ledger row, model page at `/models/<id>`, lab page, compare picker, command palette |
| A **benchmark** to `BENCHMARKS` | New ledger **column**, new sort option, a card on the homepage, its own page at `/benchmarks/<id>`, a row on every dossier and in compare, a coverage bar on `/methodology` |
| A model from a **new lab** | Its own filter chip, lab page, grouping on `/models` |

This was tested, not assumed. A fifth benchmark (`zz-testbench`) and a new model
were injected into a backed-up `catalog.ts`, and every surface above picked them
up with **zero code changes** — new ledger column, new sort-menu entry, new
benchmark page with a correct `<title>`, coverage bar, dossier row. The catalog
was then restored byte-identical (`cmp` verified).

The only things still named in code:

- `HEADLINE_BENCHMARK = "aa-intelligence"` in `derived.ts` — the board the site
  *ranks by*. Changing which index is the headline is a deliberate act.
- `BOARD_ORDER_HINT` — display order only. Unlisted benchmarks still render, they
  just sort to the end.
- A **new `LabId`** must be added to the union in `types.ts`, plus a color in
  `colors.ts` and a motif in `profiles.ts`. `npm run typecheck` names every spot.

### Mobile

The ledger is **cards below `md`, table at `md` and up**. A nine-column table on a
393px screen is a two-inch window onto the data — you can never see a row and its
columns at once, and horizontal scrolling does not fix that. Sorting on a phone is
a native `<select>`, not a row of 10px column headers behind a scroll. Filter chips
wrap rather than scroll, because a hidden horizontal overflow makes half the labs
undiscoverable. The SVG charts keep a `min-w-[600px]` inside a scroll container
rather than scaling an 860-unit viewBox down to 393px and rendering axis labels at
five pixels.

Three bugs shipped past the first QA sweep and were caught by the owner on a real
iPhone. All three came from the same mistake — testing a *resized desktop browser*
instead of a phone:

1. Magnitude bars were `hidden sm:block`, so they only existed in landscape.
2. Sort did nothing, because `setSort` lived **inside** `document.startViewTransition`.
   Where the transition does not run — iOS Safari, with dozens of named `<tr>`
   elements — the state update never happened. Animation must never decide whether
   a control works; the state update is now unconditional and the transition only
   wraps it, behind a pointer/width check and a `try`/`catch`.
3. The table's horizontal scroll left roughly 200px of visible data.

`scripts/new-qa.mjs` now has a mobile interaction pass with `isMobile`/`hasTouch`
that presses the controls and asserts on all three.

Two more hardening passes landed later the same day, both found by running the
same controls dozens of times back to back under real system load rather than
once in a quiet browser:

- **Ledger sort** (`ledger.tsx`) already wrapped `setSort` in
  `document.startViewTransition`, but the transition's own callback can be
  accepted and never invoked when the tab is under load — not just on iOS
  Safari, on a busy Chromium too. The apply is now raced against an 80ms
  `setTimeout` fallback (and `vt.ready`/`vt.finished` rejection handlers), so
  the click always lands within 80ms regardless of whether the browser ever
  gets around to running the transition.
- **Compare scroll restore** (`compare.tsx`) corrected `window.scrollY` once,
  in a single `.then()` off the navigation promise. That single check can
  itself race later reflow (new cards mounting, the Reveal observer, the
  scatter chart laying out) and lose — reproduced at roughly a 1-in-4 rate in
  testing. It now reasserts across a 700ms wall-clock window (not a fixed
  frame count — a "frame" can take well over 100ms under load) with a plain
  `setTimeout` backstop in case `requestAnimationFrame` itself gets
  deprioritized. Verified clean across two independent 4-run batches after the
  fix; `scripts/new-qa.mjs`'s iPhone-17 regression check now waits out the
  full correction window before reading the result.

### A production-only outage found on the way (fixed)

Every interactive control on **ridgebench.com** — the published site included —
was dead for anyone visiting the public hostname, and had been since nginx went
in on 2026-09-08.

`/etc/nginx/sites-available/ridge` carried a sensible dotfile guard:

```nginx
location ~ /\. { deny all; }
```

Vite dev serves its prebundled dependencies — React itself — from
`/node_modules/.vite/deps/*`. That `/.vite/` segment matched the guard, so React
returned **403**, nothing hydrated, and every button on the site did nothing. The
page looked perfect, because the server-rendered HTML was fine.

It was invisible to every check run so far because **localhost bypasses nginx**.
`http://127.0.0.1:8098` served the deps happily; `https://ridgebench.com` did not.

Fixed by narrowing the guard so it cannot match Vite's directory:

```nginx
location ~ /\.(?!vite/) { deny all; }
```

`.env` and `.git/config` are still refused. `scripts/new-qa.mjs` now asserts
through the proxy (`127.0.0.1:8099` with a `Host:` header) that the dependency
URLs load *and* that dotfiles stay denied, so this cannot regress silently.

**Lesson worth keeping:** a dev-server-backed site must be QA'd through its real
proxy chain. Passing on `localhost` proves the app works, not that the site does.

### Motion

No animation library was added. Everything is CSS or a platform API:

- Reveal-on-scroll via IntersectionObserver, **opaque by default**. A CSS
  `animation-timeline: view()` path was built and then removed — it holds
  off-screen content at `opacity: 0` until the scroll reaches it, which blanks
  full-page capture, print, and any non-scrolling context. Elements already in
  the viewport never get `data-in`, because that attribute starts the rise
  animation from opacity 0 and flashes the first paint blank. `scripts/new-qa.mjs`
  asserts against invisible content. Do not reintroduce scroll-gated opacity.
- Re-sorting the ledger uses `document.startViewTransition` + `flushSync`, so the
  row you were reading travels to its new rank. This is the one place motion
  carries information. The sort state update is applied even if the transition
  callback never runs (an 80ms fallback) — Chromium on a loaded Pi can accept
  `startViewTransition` and hang, which used to make `$/AA` a no-op.
- Sort headers and filter chips are deliberately **unanimated** — controls hit
  constantly should feel instant.
- `prefers-reduced-motion` gentles motion rather than deleting it, and covers the
  `::view-transition-*` pseudo-elements.

## QA

```bash
node scripts/new-qa.mjs      # needs the dev server up; uses the Pi's /usr/bin/chromium
```

Checks every route at 1440×900 and 390×844 for console errors, page errors,
failed requests, horizontal overflow, a missing `h1`, invisible content, and
sub-24px tap targets, then exercises sort, column expand, lab filter and the
command palette. Screenshots land in `screenshots/` (gitignored).

The heavier interaction sections (desktop sort/filter, the mobile pass, the
iPhone-17 compare pass) each relaunch Chromium rather than share the browser
the page-walk used. A single Chromium process that has already handled 28
page loads across two viewports measurably degrades on this Pi by the time it
reaches those sections — `document.startViewTransition` and rAF-driven work
that pass reliably in isolation started silently stalling, which is a
test-harness artifact, not something a real visitor (whose browser is always
fresh) would ever hit. Confirmed by running the same assertions standalone —
reliable — versus at the tail of the full sweep — reliably failing — before
the fix.
